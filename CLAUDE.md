# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Static marketing/blog site for **IA-Entrepreneur** (ia-entrepreneur.fr), a Qualiopi-certified training organization (brand of Clindit SASU) offering company AI training in three levels (plus thematic trainings: ChatGPT, Copilot, n8n/Make automation, prospection, management, sales, etc.) and turnkey AI integrations. No frontend framework, no bundler, no `package.json` — plain HTML/CSS/JS files deployed as-is (Vercel, per `vercel.json`, which redirects `www` → apex domain).

`llms.txt` at the repo root is the canonical, up-to-date summary of the business (offer, legal info, contact) — read it for business context instead of asking.

## Architecture

- **Every page is a self-contained `.html` file** — no shared header/footer include, no templating engine. The `<style>` block (design tokens as CSS custom properties: `--bg`, `--primary`, `--accent`, `--text`, etc., font: Inter via Google Fonts) is duplicated inline in each page. `mobile.css` and `nav-dropdown.css` are the only shared stylesheets, linked separately — the first for responsive overrides, the second for the header's hover menus, whose CSS could not be duplicated inline across 318 pages and stay fixable.
- **The training offer is split in two pages by audience** (2026-09-21, replacing the tabbed `formations-entreprises.html`, which is gone and 301-redirected in `vercel.json`):
  - `formation-ia-entreprise.html` — teams, intra-entreprise, built to measure, **no price anywhere**: quote only. Targets "formation IA entreprise".
  - `formation-ia-independant.html` — freelances/solopreneurs: a **waiting list** for future open sessions (to become CPF-eligible once the RS6776 habilitation lands — never say CPF on the site before that). No price, no product name.
  - **Since 2026-10-12/14 the only training offer is three levels for companies** (Gabriel's call, final): **niveau 1 · Montée en compétences / acculturation IA (1 à 2 jours)**, **niveau 2 · IA métier (2 à 3 jours)**, **niveau 3 · Automatisation & intégration (3 à 4 jours)**; groups of 12 max, 1 day = 7 h, quote only, OPCO file built to aim at zero out-of-pocket. **« IA Essentiel », « IA Métier » (as a product), « IA Pro », « Premium » and the 800 € / 1 000 € / 4 000 € / 5 000 € prices no longer exist — for companies or freelancers. Never reintroduce them.**
  - **No price for any training or any turnkey integration anywhere on the site** (2026-10-14): every amount became « Sur devis ». Third-party tool costs (API, subscriptions, Goodweek's public 32 € HT) may stay when clearly labelled as such.
  - **Retired on 2026-10-14** (pages deleted, 301 in `vercel.json`): `coaching-ia-dirigeant.html` and `audit-diagnostic-ia-entreprise.html` → `/formation-ia-entreprise.html`, `formations-creation.html` → `/`, `formateur-charly-michel.html` → `/nos-formateurs.html` (Charly left the team). Don't link to them again; the advisor's `api/_offres.js` no longer lists them.
  - Copy rules that apply everywhere (same as the sales team's Goodweek reference files): no ROI / euro gains / time-saved percentages; no « financé à 100 % », « 0 € », « reste à charge nul » — say « viser zéro reste à charge »; Qualiopi certifies the **organisation**, never « une formation certifiée Qualiopi »; AI Act art. 4 = « prendre des mesures pour développer la maîtrise de l'IA du personnel », an **obligation de moyens** since the Digital Omnibus — no fines, no « formation obligatoire » claim.
  - There is **no session calendar any more**. The old one was hardcoded June–July 2026 and had silently been showing "plus de sessions disponibles" since August. Groups now open at 3 sign-ups via the waiting-list form. Don't reintroduce hardcoded dates without a plan to keep them current.
- **Landing pages** live at the repo root (`index.html`, `formation-ia-entreprise.html`, `formateur-*.html`, `integration-*.html`, etc.) — one file per offer/page, no routing.
- **`blog/`** holds one HTML file per article (~90 articles). `blog.html` at the root is the paginated/filterable index of article cards, generated from the files in `blog/`.
- **Blog pipeline is automated via n8n**, not run locally in normal dev flow:
  - New articles are generated and pushed by an external n8n workflow (see recent git log: `Auto: Nouvel article ...` / `auto: carte blog ...` / `auto: sitemap ...` commits, often merge commits from n8n's own branch).
  - `n8n_*.js` / `n8n_system_message.txt` / `n8n_preparer_prompt.js` in the repo root are **copies of the n8n workflow's Function-node code and prompt**, kept here for reference/version control — they don't run as part of a local build.
  - `n8n_generer_html_article.js` builds the full article HTML (SEO meta, OG/Twitter tags, JSON-LD `Article` schema, hero image from Supabase storage `srmmlwvumrqcpdwwrxjh.supabase.co`).
  - **Editing these copies changes nothing on the live site until they are pasted into n8n.** Until 2026-10-05 the live workflow ran code older than the repo copies, so each new article came out with gradient text, no `mobile.css`, no dropdowns, no masked phone, links to the retired `formations-entreprises.html` and a stale Qualiopi number, and had to be retrofitted by hand. After any change to a site-wide rule, update the matching copy **and** the n8n node the same day. There is a single HTML generator copy now: the former `_v2` (the variant that reads `🔗 Maillage inter-articles`) is merged into `n8n_generer_html_article.js`, which reads the maillage node and falls back to `📝 Parser réponse`.
  - `n8n_maillage_interarticles.js` inserts internal links between articles by keyword/topic similarity.
  - `n8n_preparer_prompt.js` embeds hard 2026 facts (micro-entreprise thresholds, IS rates, etc.) that must never be invented — treat this file as the source of truth for stats used in article generation.
- **`meilleures-ia.html` + `ia/` + `data/` are the AI directory ("Les meilleures IA du moment")** — the only generated, regenerable part of the site:
  - `data/ia-tools.json` (129 tools) and `data/ia-categories.json` (16 usage categories) are the source of truth. Edit these, never the generated HTML.
  - `python3 generate_ia_pages.py` regenerates `meilleures-ia.html` (hub with search/filters/selector), `ia/<tool>.html` (one static sheet per tool), `ia/meilleures-ia-<category>.html` (one page per usage), `ia-annuaire.css` (shared stylesheet for those pages, extracted from `index.html`'s own rules so the header/footer stay identical), `ia-annuaire.js` (favourites in `localStorage` + share button, shared by all directory pages), and rewrites the directory's entries in `sitemap.xml`.
  - **All directory content is static HTML on purpose**: the JS only filters/hides cards that are already in the markup. This is the point of the whole thing vs. competitors whose directories are JS-rendered and therefore invisible to Google and to AI crawlers (see the `nos-formateurs.html` bug for the same failure mode).
  - `python3 generate_og_images.py` regenerates the 146 Open Graph cards in `images/og/` (Pillow + system fonts, no browser). Run it before `generate_ia_pages.py` when you add a tool or a category, otherwise the new page points at a missing image.
  - `add_annuaire_links.py` (nav/mobile menu/footer link on every page) and `add_annuaire_callouts.py` (in-article callouts on 11 blog posts) are idempotent and only need rerunning if new pages appear.
  - Metadata is generated under hard limits: titles ≤ 60 characters, descriptions ≤ 158, all unique across the 146 pages. `titre_seo()` / `description_seo()` in the generator pick the longest variant that fits — keep using them rather than hardcoding a title.
  - `python3 veille_annuaire.py` is the monthly watch: it re-fetches every editor URL (telling a dead link apart from a Cloudflare 403, and a rebrand from a login redirect), scrapes each editor's pricing page (~64/129 are readable; the rest go to a manual rotation list), and diffs the competitor catalogue at avantagedigital.fr/bible-des-ia. State lives in `data/veille-annuaire.json` — only differences since the last run are reported. It runs by itself through `.github/workflows/veille-annuaire.yml` (1st of each month, 07:00 UTC, also launchable by hand from the Actions tab): the workflow opens a GitHub issue when there is something to act on, and otherwise just commits the new reference state. `--markdown` produces the issue body, `--code-sortie` exits 1 when something needs attention. Crawled their 135 pages on 2026-09-04: **their site publishes no tool pricing at all**, so it is a coverage signal only, never a tariff source.
  - **`python3 verifier_coherence.py` must pass before any data commit** — it enforces the rules that keep the selector honest: an Expert tool is never offered to a Dirigeant, a Développeur tool is never `Débutant`, the copy must not contradict the declared level, the price band must match `prixDetail`, alternatives must share a usage, and every usage must contain at least one free/freemium beginner tool. It also runs in CI on every push touching `data/**`. Level criteria, printed on the page itself: *Débutant* = usable the same day with no setup; *Intermédiaire* = a logic to understand or a few days to get going; *Expert* = code, self-hosting or sysadmin skills.
  - The selector applies **usage and level as hard constraints** (never relaxed — that is what stopped n8n being recommended to a beginner), profile then budget as relaxable ones, and it tells the visitor when it had to widen. 336 combinations are covered by the browser test in the scratchpad.
  - **The advisor (`/api/conseil`)** turns a described situation into a chain of 2-4 tools ("Taplio to write the post, ChatGPT Images for the visual"), each with its role and how to use it, then the most relevant IA-Entrepreneur offer. Two tiers: the page's **local engine** answers instantly from the cards already in the DOM (weighted keyword scoring + a per-role chain), then `/api/conseil` replaces it with a tailored answer. If the API is missing, down or rate-limited, the visitor keeps the local answer and sees no error — so the feature works with or without a key.
    - `api/conseil.js` (Vercel serverless, Anthropic SDK, `claude-haiku-4-5`, forced tool schema, catalogue cached via `cache_control`). It re-validates every slug and offer key server-side and drops anything absent from the catalogue — a model that invents a tool would destroy the directory's credibility.
    - `api/_catalogue.js` is **generated** by `generate_ia_pages.py`; `api/_offres.js` is the closed list of pages the advisor may cite. The model picks a key, never a URL.
    - Env vars on Vercel: `ANTHROPIC_API_KEY` (without it the endpoint returns 503 by design), plus `SUPABASE_URL` / `SUPABASE_ANON_KEY` for the anonymous question log (table `ia_entrepreneur_questions`, insert-only RLS, no IP, no identifier).
    - `package.json` exists **only** for this function's dependency. Never add a build script to it: the site itself is still plain static HTML.
  - **`api/recap.js` sends the answer by email and feeds the nurturing list.** After a recommendation, the visitor can have the plan emailed; a separate never-pre-ticked box opts into commercial content (art. 6.1.a RGPD — the consent wording itself is archived with its timestamp, art. 7.1). The client posts **only slugs and an offer key**: the server rebuilds names, prices and links from the catalogue, so no free text from a visitor can ever reach an email — otherwise the site would be an open spam relay on its own domain. The email is composed server-side (HTML + plain text) and sent through **Brevo**, called directly rather than through an n8n detour: one email and one contact is two HTTP requests, and an intermediate workflow would only have been one more moving part to maintain. The nurturing *sequence* lives in Brevo, where it changes without touching code.
    - **`BREVO_API_KEY` is the only required variable.** Without it the endpoint returns 503 and `/api/conseil` sets `recap: false`, so the page never shows the block — no promise we cannot keep. The sender address must be a **verified sender** in Brevo or the send is rejected. `BREVO_EXPEDITEUR`, `BREVO_EXPEDITEUR_NOM` and `BREVO_LISTE_ID` override the defaults when needed.
    - The nurturing list is **resolved by name and created on first use** (folder included, reusing the first existing one) rather than demanding a numeric id copied by hand — one less value to get wrong. Cached per instance, so only the first consenting visitor costs the lookup. Nothing is created in the Brevo account until someone actually ticks the box.
    - The contact is added **only** when `consentement === true`, with `updateEnabled` so a returning visitor updates rather than duplicates. Attributes `FINDIA_OUTILS`, `FINDIA_USAGE`, `FINDIA_OFFRE`, `FINDIA_DATE` exist so the sequence can be segmented — writing to someone without knowing why they came is exactly the email people delete.
    - Emails land in `ia_entrepreneur_recaps`, a table **separate** from the question log, which must stay strictly anonymous. Both are insert-only: the anon key is public, so no SELECT policy exists and nobody can read the address list with it. Rate limit: 5 per IP per 10 minutes, plus a honeypot field and an Origin check.
    - Brevo's free plan covers this: 300 emails/day, marketing and transactional sharing the same quota, the REST API included on every plan (checked against Brevo's own pricing page and docs on 2026-09-09). A newsletter blast eats the same allowance.
    - The directory publicly states that no link is paid. **Partnerships and commissions are a stated intention, so the switch is built rather than described**: `LIENS_REMUNERES` in `generate_ia_pages.py` (currently `False`) drives every neutrality sentence at once — the 129 sheets, the 16 usage pages, the hub's two footers, the FAQ **question and answer**, and therefore the FAQPage JSON-LD. Flip it, rerun the generator, and nothing contradicts anything. With it `False` the output is byte-identical to before the mechanism existed; with it `True`, no neutrality claim survives anywhere (verified both ways).
      Two places live outside the generator and must be changed by hand the same day: `MENTION_LIENS` at the top of `api/recap.js` (the recap email's footer — the recipient has the email and the site side by side, a contradiction there is the most visible one possible) and the directory paragraph of `llms.txt`, which is what AI crawlers read and therefore what propagates furthest.
      The wording behind the flag assumes the only arrangement compatible with the Qualiopi positioning: **payment buys a labelled placement, never a rank, never a `note`, never the removal of an unflattering limit.** If it ever bought ranking, those sentences would become false and would need rewriting, not just a boolean. Note also that a site which ranks tools and is paid for placement is a comparison platform under art. L111-7 of the Code de la consommation, which requires disclosing the commercial relationship and whether it influences ranking — get it reviewed before the first sale.
      `veille_annuaire.py` flags referral parameters on editor URLs as anomalies; expect noise there once paid links exist.
  - Tool ratings are editorial (`note` /5) and tariffs are indicative — the pages say so explicitly. No affiliate links anywhere in the directory; keep it that way.
- **`quiz/` + `api/quiz.js` replace Wooclap for the trainings delivered by visio** (2026-10-26, first used for Prudence Créole, Nov 2026). `quiz/index.html` is the trainee page (`/quiz/?a=1.2`, or `/quiz/` then type the code): first name, group, optional email, one question per screen, then the correction on screen and by email. `quiz/resultats.html` is the trainer page shared in Meet: live bars every 3 s, answers and scores hidden until revealed, the 1.1/4.1 poll shown side by side, and a cumulative ranking for the training's championship. Both are `noindex` and disallowed in `robots.txt`; never link them from the site or the sitemap.
  - The question banks are `api/_quiz-*.js` (`FORMATIONS[slug]`), merged in `api/quiz.js`; a page picks its bank with `?f=<slug>` (default `prudence-creole`). **One bank per file**: Gabriel replaces `_quiz-prudence.js` wholesale when that training changes, so another quiz added inside it would vanish. `_quiz-integration.js` (`f=integration-commerciale`, groups Setter / Commerciale / Closer) is the sales-team onboarding quiz, written for Anna and also taken by the closers (Nov 2026); questions are phrased about « la setter » rather than « tu » wherever the right answer depends on the role (the price rule differs for setter and closer) and generated from the Drive « IA-Entrepreneur — Intégration Commercial » (`Goodweek/20-commercial.md` takes precedence): when those documents change, the quiz must follow. **Correct answers never reach the browser before submission**: the GET returns questions without `a`, the POST corrects server-side. Same discipline as `/api/recap`: the trainee posts option indexes only, the email is rebuilt from the bank, and the only free text (first name) is restricted to letters. Trainees are never added to a Brevo list.
  - Storage: table `quiz_reponses` (`supabase/quiz_reponses.sql`), RLS on with **no policy at all**, read and written only with `SUPABASE_SERVICE_ROLE_KEY` server-side, because it holds trainee emails. Env vars: `SUPABASE_SERVICE_ROLE_KEY`, `QUIZ_CLE_FORMATEUR` (trainer page password, sent as `X-Cle-Formateur`), `BREVO_API_KEY`; `QUIZ_EXPEDITEUR` / `QUIZ_EXPEDITEUR_NOM` override the sender. Without Brevo the page hides the email field; without Supabase the correction still shows but nothing is stored.
  - A trainee's **first** answer to an activity is the one that counts (resubmitting after seeing the correction changes nothing). Identity = normalised first name + group.
- **The phone number is never written in clear text in the HTML** (21/09/2026, security: the 06 on 310 pages was being harvested by scrapers). Every former `tel:` link is an `<a class="tel-reveal" data-tel="…">` labelled **« Afficher le numéro »**; `tel-reveal.js` (one shared file at the root, loaded with `<script defer src="/tel-reveal.js">` on every page) decodes `data-tel` (base64 of the reversed string) on click, writes the number into `.tel-value` and turns the element back into a real `tel:` link — so a second tap places the call. No digits and no `href="tel:"` remain in the source. Rules to keep it that way:
  - `masquer_telephone.py` is the idempotent migration (root + `blog/` + `ia/`); rerun it if a page ever reappears with a plain number.
  - The number lives in **four** places now: `masquer_telephone.py`, `simplifier_nav.py`, `generate_ia_pages.py` (`TEL_REVEAL_NAV` / `TEL_REVEAL_MENU` / `TEL_REVEAL_FOOTER`) and `n8n_generer_html_article.js` — all four carry the same encoded `data-tel`, never a readable number. Changing the phone number means re-encoding it (`base64(numéro inversé)`) in those four files and rerunning the generators.
  - Inside the mobile menu the page's own script closes the menu on any link click; `tel-reveal.js` reopens it after revealing, otherwise the number would appear in a menu that just shut.
  - The label is ~25px wider than the number was, in a top bar that already fitted tightly at 901px: `mobile.css` tightens `header nav a` between 901 and 1000px, and the 52 older blog articles that don't link `mobile.css` got the same rule inline plus the hamburger at 900px instead of 768px (they overflowed on tablets even before this change). `n8n_generer_html_article.js` emits both rules for new articles.
- **`data/idcc-opco.json` + `api/_opco.js` are generated** by `python3 generer_table_opco.py`, from France compétences' open-data **table SIRET-OPCO** (the dataset behind `quel-est-mon-opco.francecompetences.fr`). Never edit them by hand; rerun the script. `.github/workflows/table-opco.yml` reruns it on the 5th of each month and commits only when the data actually changed.
  - `api/opco.js` answers "which OPCO does this company belong to?" in three steps: SIRET in the official table (exact), else SIRET → IDCC → OPCO via the embedded table (a branch rule, so an IDCC determines one OPCO), else `trouve: false`. No API key: both upstream sources are public.
  - **The table only covers employers filing a DSN.** A company with no payroll, or created recently, is simply absent — verified with Clindit's own SIRET, which returns nothing. That is not a failure, and the simulator says so explicitly rather than leaving the visitor in front of an empty result.
  - Two traps handled in the generator: pseudo-IDCC **9998 and 9999** ("no collective agreement") appear across all 11 OPCO and are excluded; ~31 IDCC are genuinely shared (mostly the agricultural `8xxx`, between AKTO and OCAPIAT) and are flagged `ambigu` with their candidates, so the simulator shows "check before filing" instead of a confident wrong answer.
  - **What each OPCO actually reimburses is deliberately NOT stored.** Amounts depend on the branch *and* the headcount, and are revised at least yearly — a stale figure shown as certain would cost a visitor their funding. What is stored per OPCO is the page where **that** operator publishes its own criteria (all 11 verified 2026-09-21), plus the *shape* of the rule, which is stable. France compétences' open data covers only apprenticeship NPEC, not the plan de développement des compétences, so there is no unified source for the amounts and there will not be one.
  - The one rule true for all eleven, and the one that decides everything else: **mutualised plan-de-développement funds are reserved to companies under 50 employees**; above that the training is funded from the company's own budget or a voluntary contribution. It ships as `REGLE_COMMUNE` and is shown under every result.
  - `simulateur-financement-formation-ia.html` calls `/api/opco` and **falls back** to its local `IDCC_MAP`/`NAF_MAP` if the endpoint is unavailable, then to the sector picker. It always displays where the answer came from and the date of the data — an OPCO shown as official when it was guessed would cost the visitor a funding application.
- **No "AI-generated" visual clichés** (2026-09-22, Gabriel's call): the site must not look like an AI landing page. Concretely, and to keep this way: **no gradient on text** (the 141 `background-clip: text` rules across 139 files are gone, replaced by a solid `var(--primary)`), **no decorative background grid**, and **no blurred colour glows** (`.blob`, `.hero-photo-glow` — the homepage hero is plain white). The header's frosted `backdrop-filter: blur(18px)` stays: that is ordinary UI, not the cliché. Background gradients went too, in a second pass (221 flattened to their first non-transparent stop, 16 more in inline `style=""`, 14 decorative glow rules deleted outright).
  - **Two families are deliberately kept, and must stay**: the dark navy overlays on photos (`rgba(10,15,44,…)`, 131 of them, mostly `.article-hero::after`) exist so the white title stays readable over the image — removing them would make 122 article titles unreadable; and the header's frosted `backdrop-filter: blur(18px)`, which is ordinary UI.
  - Three cases needed different handling, which is why a blind find-and-replace would have broken things: radial glows on `.page-hero::before/::after` had to be **deleted** (flattening a fade-to-transparent produces an opaque tint — the opposite of the effect), hairline separators starting on `transparent` had to take their **middle** colour or they vanish, and gradients written with nested `var()`/`rgba()` need a paren-aware parser.
  - Two rules needed a colour other than the primary blue, because their gradient was not blue→green: `.chiffre-num` (`var(--text)`) and `.chiffre-num.accent` (`var(--accent)`) on the homepage.
- **Client logos** live in `images/references/` and are shown by the `.refs-band` section ("Ils nous font confiance") on `index.html`, `formation-ia-entreprise.html` and `formation-ia-independant.html`. The CSS block is duplicated in each page's `<style>`, like everything else here.
  - `python3 preparer_logo_reference.py <source> <slug> [--recolorer]` normalises a new logo: iterative de-framing, trim, resize to 120px high (2x of a 60px display), flatten on white, 128-colour palette. The seven originals went from 1.6 MB to ~55 KB total. Adding or swapping a logo means rechecking that the row still fits on one line: the band is sized so seven logos sit on a single row at 1120px, and a wide wordmark eats that budget fast (ACF replacing Generali pushed UX Key onto a line of its own until the scale was retuned).
  - The band **must stay on a white background**: the logos are flattened onto white, so any other backdrop shows a rectangle around them.
  - Two traps the script exists for: Apec ships with a grey frame whose four sides differ (92 to 135 grey), which a corner-colour trim cannot see — hence the line-by-line de-framing with a wide tolerance; and TurboHero is white-on-transparent, invisible on a light band, so `--recolorer` repaints its white in the site's navy and keeps the yellow bolt. Swap in the brand's own light-background version if they provide one.
  - `object-fit: contain` on the images is load-bearing: with `height` and `max-width` both set, a wide wordmark like TurboHero would be squashed without it.
  - **Displaying a client's logo is a public claim of a commercial relationship**; several of these are large accounts whose contracts restrict logo use. Check before adding a new one.
- **Navigation is generated, not hand-edited**: `simplifier_nav.py` rewrites the `<nav>` and mobile menu of every root and blog page, and also injects the `nav-dropdown.css` link; `generate_ia_pages.py` does the same for the directory pages. Change the nav in those two places and rerun both, never page by page.
  - The top bar now carries **hover dropdowns** on Formations IA, Intégrations IA and Meilleures IA (`MENUS` in `simplifier_nav.py`, `MENUS_NAV` in `generate_ia_pages.py` and `MENUS` in `n8n_generer_html_article.js` — **the three lists must stay identical**). ## Working in this repo

- There is no build/lint/test command — verify HTML changes by opening the file directly or via a static server (e.g. `python3 -m http.server`).
- When adding/editing a page, match the existing pattern: inline `<style>` block with the same CSS variable names, GA4 snippet (`G-SZG9XPNNNC`), canonical/OG/Twitter meta tags, and JSON-LD where applicable (see `blog/business-plan-guide-complet-2026.html` as a reference article, or `index.html` for a landing page).
- After adding a blog article manually (rare — normally n8n does this), run `python3 generate_blog.py` to refresh `blog.html`, and update `sitemap.xml` to keep it consistent with the git-log automation pattern (`auto: carte blog ...` + `auto: sitemap ...`).
- Don't add a JS framework, bundler, or shared templating system unless explicitly asked — the whole site intentionally has zero build step.
